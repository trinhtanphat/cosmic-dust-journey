# V3.1 Experience Design

## Status

Approved direction: Option A from issue #7. V3.1 adds interruptible autoplay, guided chapter navigation, and canonical chapter deep-links on top of the merged V3.0 visual-continuity baseline. V3.2 Capture & Quality remains a separate follow-on project.

## Goal

Make the existing ten-chapter stellar journey easy to watch, pause, resume, navigate, and share without creating a second timeline or allowing programmatic playback to fight the user.

The primary rule is **user intent always wins**: when autoplay is controlling page progress, any explicit manual navigation gesture immediately relinquishes autoplay control.

## Existing architecture to preserve

V3.1 extends the existing application rather than replacing its navigation model:

- `src/content/chapters.ts` remains authoritative for the ten authored chapters, IDs, order, copy, and `scrollLength` values.
- `src/experience/timeline.ts` remains the only normalized chapter timeline.
- `src/experience/store.ts` remains the only Zustand experience store.
- `src/app/ExperienceShell.tsx` remains the top-level DOM/renderer shell and already translates real page scroll into `globalProgress`.
- V3.0 remains authoritative for `globalProgress -> visual continuity -> camera spline -> SceneDirector`.
- `ProgressRail` remains the chapter overview/navigation surface, but its independent `scrollIntoView` behavior is replaced by the shared V3.1 controller.
- Existing WebGL fallback, adaptive quality, reduced-motion detection, audio policy, and privacy-first observability remain intact.

V3.1 must not add a router dependency, second renderer, second frame loop, second chapter timeline, or alternate state store.

## Narrative contract

## Interaction model

### Manual mode

Manual mode is the default on initial load. Existing wheel/touch/keyboard/browser scrolling remains authoritative. The app may reflect the active chapter in the URL with `history.replaceState`, but it must never snap the user merely because passive scrolling changed chapters.

### Autoplay playing

Autoplay begins only after an explicit Play action. It advances the same real page scroll used by manual navigation, so existing ScrollTrigger/store/camera/scene behavior remains authoritative.

Continuous autoplay uses normalized journey progress and `requestAnimationFrame`. Each frame converts normalized progress back into current scrollable document pixels and calls `window.scrollTo`. This avoids a synthetic second timeline and tolerates responsive layout height changes.

The default full-journey cinematic duration is a bounded authored constant derived from chapter `scrollLength` weighting. The model advances by elapsed delta time rather than frame count.

### Pause / Resume

Pause freezes programmatic advancement at the current normalized progress. Resume continues from the live store/page progress, not from stale internal playback state.

If playback has completed, Play/Resume restarts from the beginning rather than attempting to advance past 1.0.

### User takeover

The following explicit navigation gestures immediately switch playback to manual mode and cancel autoplay driving:

- `wheel`;
- `touchstart` / `touchmove`;
- navigation keys: `ArrowUp`, `ArrowDown`, `PageUp`, `PageDown`, `Home`, `End`, and Space when focus is not in an editable control.

Programmatic `scroll` events emitted by autoplay are not takeover signals. The controller listens to intent events, not generic `scroll`, to distinguish user takeover from its own page movement.

Clicks on guided navigation controls are also user intent. They stop autoplay before navigating.

## Reduced motion

`prefers-reduced-motion` remains a hard experience constraint.

V3.1 never performs continuous rAF auto-scroll while reduced motion is active. If the user explicitly starts autoplay under reduced motion, playback becomes **chapter-step mode**:

- hold the current chapter for a bounded interval;
- advance to the next chapter with instant (`behavior: 'auto'`) navigation;
- preserve pause/resume and user-takeover semantics;
- complete at the epilogue;
- do not introduce smooth scrolling.

Manual guided navigation also uses instant movement when reduced motion is active.

## Canonical deep-links

V3.1 uses the existing DOM IDs as the public shareable contract:

```text
#chapter-overture
#chapter-cold-cloud
...
#chapter-epilogue
```

No routing library is required.

### Parsing

A pure navigation model resolves a hash only when it exactly matches a known canonical chapter ID. Unknown or malformed hashes fail closed and do not move the page.

### Initial hydration

After the narrative DOM exists, the journey controller reads the initial hash once and navigates to that known chapter. Reduced motion uses an instant jump; ordinary mode may use an instant initial hydration as well to avoid an unnecessary startup animation.

### Hash changes

External hash changes (browser back/forward, pasted URL changes) resolve through the same controller. They stop autoplay because they represent user/browser navigation intent.

### Passive URL reflection

When the active chapter changes from ordinary scrolling or autoplay, V3.1 may call `history.replaceState` with the canonical hash. `replaceState` is required rather than assigning `location.hash`, because passive reflection must not create history spam or trigger a second browser scroll.

### Guided navigation history

Explicit chapter navigation from the rail or Previous/Next buttons uses `history.pushState` before moving to the target chapter so browser Back can retrace explicit chapter choices.

## Core navigation model

Create `src/experience/navigation.ts` as a pure dependency-light model.

Required exports:

```ts
export function canonicalChapterHash(chapterId: string): string;
export function chapterIdFromHash(hash: string, knownIds: readonly string[]): string | null;
export function chapterStartProgress(timeline: readonly TimelineChapter[], chapterId: string): number | null;
export function progressToScrollY(progress: number, scrollHeight: number, viewportHeight: number): number;
export function scrollYToProgress(scrollY: number, scrollHeight: number, viewportHeight: number): number;
```

All numeric input is normalized and clamped. Unknown chapter IDs return `null` instead of throwing.

## Autoplay model

Create `src/experience/autoplay.ts` as a pure model.

Playback state:

```ts
export type PlaybackMode = 'manual' | 'playing' | 'paused' | 'completed';

export interface PlaybackState {
  mode: PlaybackMode;
}
```

Required exports include:

```ts
export function reducePlayback(state: PlaybackState, event: PlaybackEvent): PlaybackState;
export function advancePlaybackProgress(progress: number, deltaMs: number, totalDurationMs: number): number;
```

The reducer owns only mode transitions. It does not access DOM, timers, window, React, or Zustand.

Expected transitions:

- manual + play -> playing;
- playing + pause -> paused;
- paused + resume -> playing;
- playing/paused + takeover -> manual;
- playing + complete -> completed;
- completed + play -> playing (controller restarts progress at 0 first).

Progress advancement is deterministic, delta-time based, and clamps to `0..1`.

## DOM controller hook

Create `src/experience/useJourneyNavigation.ts` as the single DOM-facing orchestration unit.

It consumes:

- `globalProgress`, `chapterId`, `chapterIndex`, and `quality.reducedMotion` from the existing store;
- the existing `chapterTimeline`;
- browser `window`, `document`, `history`, and animation/timer APIs.

It returns a compact controller interface:

```ts
export interface JourneyNavigationController {
  mode: PlaybackMode;
  play(): void;
  pause(): void;
  resume(): void;
  previous(): void;
  next(): void;
  goToChapter(chapterId: string): void;
}
```

Responsibilities:

1. hydrate the initial canonical deep-link;
2. handle `hashchange`;
3. reflect active chapter hashes with `replaceState`;
4. drive continuous autoplay through real window scroll in ordinary-motion mode;
5. drive chapter-step autoplay under reduced motion;
6. install/remove takeover listeners;
7. expose guided chapter navigation methods;
8. cancel all rAF/timers/listeners on unmount.

The hook must not calculate cinematic/camera/scene state.

## Control UI

Create `src/components/JourneyControls.tsx`.

The component is presentation-only and receives the controller or specific callbacks/state as props.

Required behavior:

- manual/completed: show Play (completed Play restarts from beginning through the controller);
- playing: show Pause;
- paused: show Resume;
- always expose Previous and Next chapter controls when a valid target exists;
- use semantic `<button type="button">` controls;
- expose an accessible status such as `Autoplay playing`, `Autoplay paused`, or `Manual navigation`;
- do not hide the existing SoundToggle or ProgressRail.

`ExperienceShell` creates the controller once and passes `goToChapter` to `ProgressRail` and the relevant callbacks/state to `JourneyControls`.

## ProgressRail evolution

`ProgressRail` becomes a controlled navigation surface:

```ts
export default function ProgressRail({ onNavigate }: { onNavigate(chapterId: string): void })
```

Buttons continue reflecting active chapter state, but click handling calls `onNavigate(chapter.id)` instead of directly querying the DOM.

This removes the second navigation implementation.

## Error handling

V3.1 navigation fails closed:

- unknown hashes are ignored;
- unknown chapter IDs are ignored;
- missing target DOM elements do not throw;
- invalid numeric progress/scroll measurements clamp safely;
- `scrollHeight <= viewportHeight` maps to progress/scroll 0;
- autoplay completion cancels future rAF/timer work;
- browser APIs are accessed only inside effects/callbacks, not pure models.

## Observability

No new analytics provider is added.

V3.1 does not need raw gesture logging. Existing chapter-enter/journey-complete telemetry remains authoritative. If playback telemetry is added, it must be categorical only (`start`, `pause`, `resume`, `takeover`, `complete`) and must not record raw wheel/touch/key payloads, URLs, or pointer coordinates.

## Styling

Extend `src/styles/global.css` using the existing visual language. Controls should remain compact, translucent, readable against the cinematic canvas, keyboard-focus visible, and usable on mobile without obscuring chapter copy.

No new UI framework or icon dependency is required.

## Testing strategy

### Node core tests

Add deterministic tests for:

- canonical hash generation/parsing;
- malformed/unknown hash rejection;
- chapter start lookup;
- scroll/progress conversion and numeric clamping;
- playback reducer transitions;
- delta-time progress advancement;
- completion/restart semantics;
- reduced-motion step target logic if extracted into the pure model.

### Vitest/component tests

Cover:

- `ProgressRail` delegates navigation through `onNavigate`;
- `JourneyControls` labels/actions for manual, playing, paused, and completed modes;
- Previous/Next disabled/hidden state at journey ends;
- no authored chapter copy/order change.

### Playwright

Add V3.1 browser coverage for:

- direct load to a canonical chapter hash;
- explicit rail/Prev/Next navigation updates URL and page chapter;
- autoplay advances journey progress;
- Pause leaves progress stable over a bounded observation interval;
- Resume continues from live progress;
- wheel takeover immediately exits autoplay;
- keyboard takeover exits autoplay;
- reduced-motion autoplay advances by chapter step without smooth continuous scrolling;
- existing V3.0 boundary and V2.1 recovery/observability suites remain green.

## Performance constraints

- One active rAF loop only while ordinary-motion autoplay is playing.
- No polling loop in manual or paused mode.
- Reduced-motion autoplay uses one bounded timer, not rAF scrolling.
- Do not add per-frame React state beyond the existing scroll-driven store updates.
- Do not force layout repeatedly beyond reading current scrollable height when an autoplay frame needs to convert normalized progress to pixels.

## Out of scope

V3.1 does not include:

- screenshot/pixel baseline capture;
- recording/export/video generation;
- visual regression artifact management;
- renderer fidelity changes;
- chapter copy/science changes;
- external router/state/UI dependencies;
- new analytics providers;
- deployment architecture changes.

These belong to V3.2 or later dedicated work.
