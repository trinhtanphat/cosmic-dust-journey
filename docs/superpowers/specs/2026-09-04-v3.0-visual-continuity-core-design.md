# V3.0 Visual Continuity Core Design

## Status

Approved in chat on 2026-09-04. This spec defines only V3.0. V3.1 Experience and V3.2 Capture & Quality remain separate follow-on projects.

## Goal

Turn the existing ten-chapter V2.1 cinematic experience into a visually continuous stellar lifecycle while preserving the semantic chapter contract, authored scientific copy, accessibility fallback, reduced-motion behavior, adaptive runtime quality, and privacy-first observability.

V3.0 must make the journey feel as if the same matter, camera space, and visual energy evolve from chapter to chapter instead of independent scene components fading into one another.

## Existing architecture to preserve

The current application already provides the correct foundations and should be evolved rather than replaced:

- `src/content/chapters.ts` owns ten semantic chapters and their authored narrative.
- `src/experience/cinematicProfiles.ts` owns chapter-specific camera, transition, post-processing, interaction, and particle intent.
- `src/experience/cameraTrack.ts` deterministically samples camera tracks.
- `src/experience/cinematicState.ts` resolves chapter-local cinematic state and quality budgets.
- `src/scenes/SceneDirector.tsx` chooses current and next scene components.
- `src/experience/ExperienceCanvas.tsx` owns the persistent React Three Fiber canvas, camera rig, adaptive frame probe, WebGL recovery, and post-processing.
- V2.1 observability and recovery remain authoritative for diagnostics, WebGL fallback, and failure isolation.

V3.0 must not introduce a second renderer, second frame loop, second chapter timeline, or alternate state store.

## Narrative contract

The ten chapter IDs, order, and authored copy remain unchanged:

1. `overture`
2. `cold-cloud`
3. `collapse`
4. `ignition`
5. `main-sequence`
6. `red-giant`
7. `shedding`
8. `white-dwarf`
9. `elsewhere`
10. `epilogue`

V3.0 may change `scrollLength`, camera composition, phase timing, transition timing, material transfer, scene overlap, and render choreography. It must not rewrite the scientific narrative or reorder chapters.

The black-hole `elsewhere` chapter remains an explicitly alternate stellar outcome and must visually branch without implying that the preceding white dwarf physically turns into a black hole.

## Architectural approach

Introduce a deterministic continuity layer between cinematic state resolution and scene rendering.

The continuity layer resolves four related outputs for every frame:

1. **Matter continuity** — how much authored visual matter is inherited from the previous chapter, transformed by the current chapter, or prepared for the next chapter.
2. **Camera continuity** — one globally continuous camera route assembled from chapter-local anchors and tangents rather than ten isolated start/end lerps.
3. **Transition continuity** — scene overlap is driven by semantic material-transfer modes rather than opacity alone.
4. **Visual energy continuity** — exposure, bloom, density, turbulence, color temperature, and secondary-layer intensity evolve continuously and remain bounded by adaptive quality.

The continuity resolver is pure and deterministic. React Three Fiber components consume its output but do not own narrative state.

## New core model

Create `src/experience/visualContinuity.ts` as a pure model.

### Types

```ts
export type MatterChannel =
  | 'dust'
  | 'gas'
  | 'core'
  | 'envelope'
  | 'ejecta'
  | 'remnant'
  | 'accretion';

export interface MatterState {
  channel: MatterChannel;
  amount: number;
  density: number;
  temperature: number;
  turbulence: number;
  expansion: number;
}

export interface ContinuityEnergy {
  luminosity: number;
  bloomBias: number;
  exposureBias: number;
  turbulence: number;
  chromaticBias: number;
}

export interface ContinuityBlend {
  outgoingWeight: number;
  incomingWeight: number;
  transfer: number;
}

export interface VisualContinuityState {
  previousScene: SceneId;
  currentScene: SceneId;
  nextScene: SceneId;
  matter: readonly MatterState[];
  blend: ContinuityBlend;
  energy: ContinuityEnergy;
}
```

All scalar values are clamped to documented bounded ranges. No timestamp, randomness, DOM measurement, or renderer object may enter this model.

### Resolver

```ts
export function resolveVisualContinuity(input: {
  chapterIndex: number;
  localProgress: number;
  reducedMotion: boolean;
}): VisualContinuityState;
```

The resolver derives state from chapter position only. It must produce identical output for identical input.

## Matter continuity rules

V3.0 represents material continuity as semantic channels, not a literal particle identity registry. This keeps the system deterministic, bounded, and compatible with adaptive particle budgets.

### Overture -> Cold cloud

- Dust remains the same dominant channel.
- Density rises gradually.
- Turbulence narrows toward denser knots.
- No full scene reset.

### Cold cloud -> Collapse

- Dust and gas transfer into a denser central flow.
- Angular motion and central concentration increase continuously.
- The existing collapse scene receives inherited dust/gas weights rather than starting from zero.

### Collapse -> Ignition

- Gas/core density peaks.
- A compact `core` channel gains luminosity before the ignition flash.
- Flash energy is a bounded impulse layered on top of the already-present core, not a hard scene cut.

### Ignition -> Main sequence

- Core luminosity stabilizes.
- Envelope channel expands into a stable stellar surface.
- Residual gas/dust fades more slowly than the current crossfade to avoid a visual reset.

### Main sequence -> Red giant

- The same `core` persists.
- `envelope` radius and turbulence increase while luminosity/color temperature shift continuously.
- Camera pullback and envelope expansion are synchronized.

### Red giant -> Shedding

- Outer `envelope` mass transfers into `ejecta` shells.
- The remnant remains visible during shell formation.
- Ejecta should inherit angular phase/turbulence intent so the transition reads as the same material leaving the star.

### Shedding -> White dwarf

- Ejecta continues expanding beyond the central remnant.
- `remnant` becomes dominant while nebular density decreases.
- The nebula must not vanish at the white-dwarf chapter boundary.

### White dwarf -> Elsewhere

This is a narrative branch, not material continuation.

- The current white-dwarf material fades into a neutral deep-space bridge.
- The black-hole system is introduced as a distinct remote system.
- `transfer` is intentionally near zero for remnant -> accretion.
- Copy and visual staging must make the alternate-outcome semantics clear.

### Elsewhere -> Epilogue

- Accretion energy decays into a wide field.
- Dust/gas motifs return as a symbolic cycle rather than claiming direct physical identity.
- Final composition reconnects to the opening visual language.

## Transition modes

Keep the existing `TransitionMode` API for compatibility, but add semantic transfer interpretation in the continuity resolver.

Existing modes remain valid:

- `crossfade`
- `morph-density`
- `radial-collapse`
- `radial-expansion`
- `shell-ejection`
- `dissolve-to-point`
- `accretion-warp`
- `flash-cut`

V3.0 changes their implementation semantics:

- opacity is only one output;
- transfer amount drives particle/material weights;
- density/radius/turbulence are allowed to bridge scenes;
- reduced motion keeps the same material continuity with smaller camera and deformation amplitudes.

No new transition mode is required unless implementation proves an existing mode cannot express a required transfer.

## Continuous camera spline

The current camera sampler linearly interpolates chapter-local keyframes with smoothstep. V3.0 should preserve the data-driven profile model but assemble the authored chapter anchors into a continuous cubic route.

Create `src/experience/cameraSpline.ts`.

### Public interface

```ts
export interface CameraSplineSample extends CameraPose {
  chapterIndex: number;
  chapterProgress: number;
}

export function sampleGlobalCameraSpline(input: {
  chapterIndex: number;
  localProgress: number;
  pointer: { x: number; y: number };
  reducedMotion: boolean;
}): CameraSplineSample;
```

### Rules

- Use deterministic cubic Hermite/Catmull-Rom-style interpolation over authored chapter boundary anchors.
- Ensure positional continuity and first-derivative continuity at normal chapter boundaries.
- FOV follows a continuous scalar curve.
- Target interpolation is continuous and must not snap at chapter changes.
- Pointer influence stays bounded and additive after base spline sampling.
- Reduced-motion scales tangent amplitude, micro-parallax, and pointer influence without changing chapter order or semantic timing.
- The `elsewhere` branch may use a deliberately larger spatial bridge, but position/FOV still remain continuous.

`cameraTrack.ts` remains available for compatibility tests and any isolated profile tooling, but the live V3.0 canvas should consume the global spline.

## Visual energy continuity

Create `src/experience/visualEnergy.ts` or keep the energy resolver inside `visualContinuity.ts` if the implementation remains small. Split only if the file would otherwise mix unrelated concerns.

Energy values are authored from existing chapter post-processing intent and continuity state:

- `luminosity`: 0..1.5
- `bloomBias`: -0.35..0.45
- `exposureBias`: -0.3..0.35
- `turbulence`: 0..1
- `chromaticBias`: 0..0.15

The final `PostProcessingRig` state remains bounded by adaptive quality. V3.0 cannot force expensive post-processing back on when runtime quality has disabled it.

## Scene rendering contract

Extend `SceneProps` with optional continuity state rather than making individual scenes read the global store.

```ts
continuity?: VisualContinuityState;
```

`SceneDirector` becomes responsible for computing current/next scene render weights from `VisualContinuityState` and passing it into both scene components.

Individual scenes should read only the channels they understand:

- `DustCloudScene`: dust/gas density, turbulence, transfer.
- `CollapseScene`: dust/gas/core concentration and angular-energy intent.
- `FusionScene`: core luminosity and flash energy.
- `MainSequenceScene`: core/envelope state.
- `RedGiantScene`: core/envelope expansion/turbulence.
- `NebulaScene`: ejecta/remnant state.
- `WhiteDwarfScene`: remnant/ejecta state.
- `BlackHoleScene`: accretion energy only; it must not consume white-dwarf remnant transfer as physical continuity.

Scenes remain rendering units. They must not mutate continuity state.

## Volumetric dust and nebula

V3.0 upgrades depth perception without introducing external volumetric libraries.

Use layered procedural point/sprite fields and shader noise already compatible with Three.js/R3F.

Required characteristics:

- at least three depth bands on full quality;
- depth-aware opacity/density;
- deterministic seeded placement;
- motion derived from progress and continuity turbulence, not wall-clock randomness;
- low/adaptive quality may reduce layers and particle counts while keeping the same silhouette and transfer semantics.

No texture or asset dependency from the reference site may be introduced.

## Stellar surface continuity

Main-sequence and red-giant surfaces should share one authored stellar-surface shader vocabulary.

Create a reusable shader/material helper under `src/shaders/` or `src/scenes/shared/` according to the existing local pattern.

The material must expose bounded inputs for:

- radius/expansion;
- color temperature intent;
- surface turbulence;
- limb glow;
- luminosity;
- quality complexity.

The red giant should read as an evolution of the same star, not a replacement mesh with unrelated phase/noise.

Reduced quality may collapse secondary noise octaves but must preserve radius and color continuity.

## Black-hole lensing upgrade

The black-hole chapter remains an artistic approximation rather than physically exact general-relativistic ray tracing.

V3.0 improves the authored effect using a bounded screen/world-space distortion around the compact object and accretion disk.

Requirements:

- lensing-like distortion is strongest near the compact center and decays smoothly;
- accretion disk has asymmetric brightness/temperature variation to strengthen orbital depth;
- no unbounded full-screen ray-march loop;
- adaptive quality can disable expensive secondary distortion while preserving the silhouette and disk motion;
- reduced motion lowers warp amplitude and camera motion;
- diagnostics must remain within the existing V2.1 frame pipeline.

## SceneDirector evolution

`SceneDirector` remains the only component that chooses renderable scene components.

V3.0 flow:

```text
chapterIndex + localProgress
        |
        +--> resolveCinematicState
        |
        +--> resolveVisualContinuity
        |
        +--> sampleGlobalCameraSpline
        |
        v
SceneDirector -> Current Scene + Next Scene
        |              |
        +---- shared continuity state ----+
```

Do not mount more than the current and next authored scene families during normal transition rendering. This prevents V3.0 from turning continuity into an unbounded all-scenes-at-once renderer.

## Scroll timing

V3.0 may tune `scrollLength` values but retains ten semantic sections.

Recommended cinematic pacing:

- overture: long atmospheric entry;
- cold-cloud: gradual compression;
- collapse: longer acceleration and camera dolly;
- ignition: shorter, sharper event;
- main-sequence: longest stable chapter;
- red-giant: deliberate expansion;
- shedding: extended shell reveal;
- white-dwarf: quieter decompression;
- elsewhere: distinct alternate-branch bridge;
- epilogue: long final pullback.

Exact values belong in implementation and regression tests, not this design, provided no chapter is removed or reordered.

## Adaptive quality

V3.0 must use the existing runtime-quality state as a hard budget source.

Quality degradation order for new work:

1. reduce secondary volumetric layers;
2. reduce particle density;
3. reduce stellar-surface noise octaves;
4. disable secondary lensing distortion;
5. reduce post-processing intensity/availability according to existing budget;
6. preserve primary geometry, narrative continuity, and camera route.

No quality transition may reset chapter progress or continuity state.

## Accessibility and fallback

- Semantic narrative remains DOM-first and fully readable without WebGL.
- WebGL startup/runtime fallback continues to use V2.1 recovery behavior.
- Reduced-motion keeps the same chapter sequence and visual matter relationships, but lowers spline tangent amplitude, deformation, turbulence motion, lensing warp, and micro-parallax.
- Sound behavior remains unchanged in V3.0.
- Critical scientific meaning cannot depend on a shader-only visual cue.

## Observability

V3.0 extends existing local diagnostics only with bounded categorical/aggregate values if needed.

Allowed additions include:

- continuity mode identifier;
- active matter-channel count;
- camera spline segment index;
- optional aggregate continuity fallback counter.

Do not record raw pointer coordinates, narrative text, full camera vectors, URLs, identifiers, or per-particle data.

No new analytics provider is required.

## Error handling

The continuity model is pure and must fail closed to safe defaults for invalid numeric inputs:

- chapter index clamped to valid range;
- progress clamped to `0..1`;
- NaN/infinite scalar input normalized;
- matter/energy outputs clamped to documented bounds.

Renderer-specific failure remains contained by the existing renderer error boundary and WebGL recovery path.

If a scene cannot interpret a continuity channel, it ignores that channel rather than throwing.

## Testing strategy

### Core deterministic tests

Add dependency-light tests for:

- chapter boundary continuity;
- matter-channel transfer rules;
- white-dwarf -> elsewhere branch isolation;
- deterministic identical-input output;
- numeric clamping;
- reduced-motion amplitude reduction;
- global camera position/FOV/target continuity at every chapter boundary;
- no chapter reorder or copy changes;
- adaptive-quality preservation of primary continuity semantics.

### Vitest/component tests

Cover:

- `SceneDirector` passes continuity into current and next scenes;
- no more than two scene families mount during a transition;
- current/next weights remain bounded;
- black-hole scene does not receive physical remnant transfer;
- ExperienceCanvas uses the global camera spline;
- WebGL fallback still leaves narrative DOM intact.

### Playwright visual QA

Extend the existing browser suite with deterministic V3.0 checkpoints around boundaries, not only chapter centers.

Required checkpoints:

- overture -> cold-cloud transfer;
- cold-cloud -> collapse density continuity;
- collapse -> ignition pre-flash core;
- ignition -> main-sequence stabilization;
- main-sequence -> red-giant radius continuity;
- red-giant -> shedding shell transfer;
- shedding -> white-dwarf retained nebula;
- white-dwarf -> elsewhere branch bridge;
- elsewhere -> epilogue cycle return.

Desktop and mobile must both be exercised. Reduced-motion must receive at least one boundary checkpoint.

Visual checks are evidence for human review; they are not required to become brittle pixel-perfect baselines in V3.0. Pixel-baseline capture belongs to V3.2.

## Performance constraints

V3.0 must reuse the existing single R3F frame stream and V2.1 diagnostics.

Hard constraints:

- no second `requestAnimationFrame`/FPS monitor;
- no per-frame particle-array allocation proportional to particle count;
- no all-scenes simultaneous rendering;
- no unbounded shader loops;
- no quality path that bypasses the runtime budget.

Performance warnings and diagnostics continue to use the V2.1 policy rather than introducing a second CI performance system.

## Deployment compatibility

V3.0 must preserve all current deployment targets:

- GitHub Pages repository base path;
- Vercel root base;
- Cloudflare Pages root base;
- Cloudflare Workers Static Assets.

No server-side runtime is introduced.

## Clean-room / provenance constraints

- No proprietary reference JavaScript, GLSL, textures, artwork, copy, or audio may be copied, recovered, de-minified, or transplanted.
- V3.0 effects must be newly authored from public visual behavior and general graphics techniques.
- Existing repository provenance tooling remains unchanged unless a new authored asset requires an explicit provenance record.

## Delivery decomposition

V3.0 should be implemented as one feature carrier with reviewable internal commits, but the implementation plan must split work into independently testable tasks:

1. deterministic continuity model and tests;
2. global camera spline and boundary tests;
3. SceneDirector/SceneProps integration;
4. dust/collapse/fusion transfer rendering;
5. stellar-surface continuity for main-sequence/red-giant;
6. nebula/white-dwarf ejecta-remnant continuity;
7. black-hole branch bridge and lensing upgrade;
8. adaptive/reduced-motion integration;
9. Playwright boundary evidence, documentation, release metadata.

V3.1 and V3.2 are explicitly out of scope for this carrier.

## Merge gate

Do not merge V3.0 to `main` until all of the following are true on the exact PR head:

- dependency-light core tests pass;
- TypeScript, ESLint, Vitest, and production build pass;
- Playwright desktop/mobile suite passes;
- V3.0 boundary screenshots have been reviewed for discontinuity, clipping, unreadable copy, excessive bloom/fringe, or obvious scene resets;
- existing V2.1 observability/privacy/WebGL/audio tests remain green;
- GitHub Pages artifact path guards remain green;
- after merge, Pages build/deploy succeeds on the resulting `main` SHA.

## Non-goals

V3.0 does not implement:

- guided/autoplay mode;
- chapter deep links;
- new interaction systems beyond what continuity rendering needs;
- capture UI;
- committed pixel-perfect visual baselines;
- a new telemetry provider;
- server APIs;
- exact GR ray tracing;
- narrative reordering or copy rewrite.

Those belong to V3.1, V3.2, or a later dedicated project.
