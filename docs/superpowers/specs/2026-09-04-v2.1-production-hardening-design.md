# V2.1 Production Hardening Design

**Date:** 2026-09-04  
**Status:** Approved architecture, pending implementation plan  
**Base:** `v2.0.0` release metadata on `main` at `16aaa2350751577b45e0beb38a33e1bbc0648223`

## 1. Goal

V2.1 hardens Cosmic Dust Journey for production without changing the authored stellar narrative or V2 cinematic semantics. The release adds a privacy-first observability layer, optional external telemetry adapters, deterministic performance diagnostics, bounded failure recovery, stronger audio/WebGL lifecycle handling, and CI evidence that can be reviewed independently of the runtime.

The system must combine all three requested modes:

- **A — Privacy-first local observability:** always available, no external network dependency, no cookies, bounded in-memory diagnostics, CI artifacts.
- **B — External observability:** optional Sentry plus privacy-aware analytics providers.
- **C — Adapter-ready opt-in:** external providers are disabled by default and can be enabled per deployment without coupling application components to provider SDKs.

## 2. Non-goals

V2.1 does **not** redesign chapter choreography, add new stellar scenes, replace the V2 adaptive-quality policy, or introduce V3 visual features. It must not change chapter timing, cinematic phase semantics, pointer interaction behavior, narrative copy, or the default muted-audio consent model.

V2.1 also does not require a backend service. Local-only mode remains a complete supported production mode.

## 3. Architecture

### 3.1 ObservabilityHub

Add a provider-neutral `ObservabilityHub` between runtime subsystems and telemetry sinks.

```text
React / WebGL / Audio / Navigation / Adaptive Quality
                         |
                         v
                  ObservabilityHub
               /          |          \
        Local ring      Sentry      Analytics
          buffer        adapter      adapters
             |                        /     \
             v                 Plausible    GA4
      CI diagnostics
```

No scene, renderer, React component, audio controller, or quality policy may call Sentry/Plausible/GA4 directly. Runtime code emits normalized events and metrics to the hub; adapters receive only sanitized payloads.

### 3.2 Proposed modules

- `src/observability/types.ts` — normalized event/metric contracts.
- `src/observability/hub.ts` — bounded ring buffer, adapter fan-out, circuit-breaker behavior, sanitization boundary.
- `src/observability/config.ts` — environment flag parsing and privacy-policy resolution.
- `src/observability/local.ts` — local diagnostics accumulator and export snapshot.
- `src/observability/performance.ts` — PerformanceObserver integration and frame diagnostics aggregation.
- `src/observability/adapters/sentry.ts` — lazy optional Sentry adapter.
- `src/observability/adapters/plausible.ts` — optional Plausible adapter.
- `src/observability/adapters/ga4.ts` — optional GA4 adapter.
- `src/components/RuntimeErrorBoundary.tsx` — isolate canvas/render failures without removing narrative DOM.
- `src/experience/WebGLRecoveryBoundary.tsx` or equivalent renderer-boundary module — bounded context-loss recovery and fallback.

Exact filenames may be adjusted in the implementation plan if the same boundaries are preserved.

## 4. Privacy and telemetry policy

### 4.1 Default mode

Default production configuration is local-only:

```text
VITE_TELEMETRY_MODE=local
VITE_SENTRY_ENABLED=false
VITE_PLAUSIBLE_ENABLED=false
VITE_GA4_ENABLED=false
```

External provider code must not load when disabled.

### 4.2 Sanitization

The hub must not collect or forward:

- pointer coordinates;
- narrative text contents;
- arbitrary query strings;
- form data;
- email, account, device identifiers, or user IDs;
- raw URLs containing query/hash data;
- full stack-linked browser storage values.

Allowed contextual fields are bounded enums/numbers such as chapter id, scene id, cinematic phase, adaptive quality level, quality tier, browser capability flags, coarse viewport class, error class, and performance aggregates.

### 4.3 DNT and Global Privacy Control

When `navigator.doNotTrack` indicates opt-out or `navigator.globalPrivacyControl === true`:

- analytics adapters are disabled regardless of environment flags;
- local diagnostics continue to operate;
- error reporting may remain independently configurable but still passes through sanitization and contains no analytics identity.

### 4.4 External adapter resilience

Every adapter is fail-open from the application's perspective:

- provider initialization failures do not throw into app runtime;
- transport failures are bounded and do not retry forever;
- a failing adapter is circuit-broken for the session after a small bounded failure count;
- hub delivery never blocks rendering or scroll progression;
- external telemetry cannot influence cinematic state or adaptive-quality decisions.

## 5. Performance diagnostics

### 5.1 Single frame source

V2 already samples frame duration in `FrameQualityProbe` and applies hysteresis through `observeFrame`. V2.1 must preserve a **single authoritative frame-timing stream**. The sampling boundary may be extracted from `ExperienceCanvas`, but no second competing FPS loop may be added.

The same frame sample may feed both:

1. existing adaptive-quality state; and
2. observability aggregation.

Observability is read-only with respect to narrative progress.

### 5.2 Collected local metrics

Bounded diagnostics should include:

- frame count;
- p50/p95/p99 frame time;
- percent of frames above 50 ms;
- maximum frame time;
- long-task counts and maximum long-task duration;
- adaptive-quality level transitions;
- time spent at each adaptive level;
- WebGL context-loss and restore counts;
- runtime/React error count;
- audio lifecycle state changes;
- chapter transition timing summaries;
- heap measurements when the browser exposes a supported memory API.

Metrics must be aggregated rather than retaining an unbounded raw stream.

## 6. Performance budgets

### 6.1 Desktop Chromium CI target

- frame-time p95 target: **<= 35 ms**;
- frames >50 ms: **<= 5%**;
- JavaScript/runtime errors: **0**;
- WebGL context-loss during normal journey: **0**;
- long tasks >250 ms: **<= 2 per journey**;
- long tasks >1,000 ms: **0**.

### 6.2 Mobile Pixel 7 emulation target

- frame-time p95 target: **<= 50 ms**;
- frames >50 ms: **<= 10%**;
- JavaScript/runtime errors: **0**;
- WebGL context-loss during normal journey: **0**;
- no persistent adaptive-quality level 3 after the workload stabilizes.

### 6.3 Heap budget

Heap growth is reported when a supported Chromium memory API is available. To avoid flaky CI, heap is a warning/trend metric by default and becomes a hard failure only for clearly abnormal growth greater than **128 MB** across one deterministic journey, excluding unsupported browsers.

### 6.4 CI philosophy

Hard-fail only stable failures:

- JS/runtime errors;
- unhandled rejection;
- WebGL loss in the normal journey;
- extreme long task >1 s;
- missing diagnostics artifact;
- broken recovery tests;
- privacy/telemetry contract violations.

Frame percentiles and memory thresholds use conservative budgets and should produce actionable reports rather than brittle noise. If CI infrastructure proves too noisy for a budget, the implementation plan must separate it into a reported warning instead of silently removing the metric.

## 7. Failure recovery

### 7.1 WebGL startup failure

Existing `supportsWebGL()` behavior remains the initial capability gate. Failure renders `WebGLFallback` while preserving all DOM narrative content and navigation.

### 7.2 Runtime WebGL context loss

On `webglcontextlost`:

1. record a sanitized local event;
2. pause or unmount heavy rendering work;
3. allow one bounded restore path;
4. on successful restore, recreate/remount renderer state without changing chapter progress;
5. if restoration fails or a second loss occurs in the session, enter permanent WebGL fallback for that session.

Recovery must never enter an infinite remount loop.

### 7.3 React/render failure

A dedicated error boundary isolates the canvas/render subsystem. A renderer exception must not remove:

- the story DOM;
- progress/navigation UI that can function without WebGL;
- accessibility content;
- footer/return navigation.

The boundary records an error event and switches to the static fallback presentation.

### 7.4 Audio lifecycle

Current explicit user consent is preserved. V2.1 hardens the controller so:

- no audio starts before explicit user enablement;
- `suspended`/`interrupted` contexts are observed;
- tab background/foreground does not create duplicate oscillator graphs;
- automatic browser suspension does not trigger unsolicited autoplay;
- resume requires a valid user gesture when the platform requires it;
- `stop()`/`dispose()` remain idempotent and release all source nodes;
- lifecycle events can be observed locally without recording user-identifying data.

### 7.5 Telemetry failure

Sentry, Plausible, and GA4 failures are non-fatal. Provider errors are never re-emitted as application errors through the same hub recursively.

## 8. External adapters

### 8.1 Sentry

Sentry is optional and lazy-loaded only when explicitly enabled. It may receive:

- sanitized uncaught exceptions;
- unhandled rejections;
- WebGL initialization/context-loss failures;
- bounded sampled performance spans if configured.

No user identity is attached by default.

### 8.2 Plausible

Plausible is the preferred privacy-oriented analytics adapter. Allowed aggregate events include chapter entry, journey completion, sound-enabled state transition, and coarse interaction category. No raw coordinates or custom PII fields are allowed.

### 8.3 GA4

GA4 is optional for deployments that explicitly require it. It uses the same sanitized analytics contract and is disabled by DNT/GPC. The application must remain fully functional if GA4 is blocked by the browser or network.

## 9. CI and artifacts

Extend the PR CI with deterministic observability/performance diagnostics while preserving existing static/unit and browser visual checks.

Expected artifact layout:

```text
v2.1-diagnostics/
  performance-diagnostics.json
  performance-summary.md
  visual-checkpoints/
  test-results/
```

`performance-diagnostics.json` must be machine-readable and include schema/version metadata plus browser project metadata. `performance-summary.md` must summarize pass/warn/fail budgets for humans.

Playwright must continue to cover at least:

- Chromium desktop;
- Chromium mobile / Pixel 7 emulation;
- reduced-motion path;
- all existing visual checkpoints.

Add targeted recovery/privacy tests for:

- WebGL startup fallback;
- bounded context-loss recovery;
- renderer ErrorBoundary fallback;
- telemetry disabled by default;
- DNT/GPC analytics suppression;
- provider failure isolation;
- audio lifecycle idempotency;
- diagnostics artifact generation.

## 10. Deployment configuration

V2.1 must remain deployable on GitHub Pages, Vercel, and Cloudflare static assets without requiring provider secrets. External telemetry is enabled only by build/deployment environment variables.

Provider configuration must not be committed with real DSNs, measurement IDs, API keys, or secrets.

## 11. Testing strategy

Implementation follows TDD:

- pure unit tests first for configuration, sanitization, ring buffer, circuit breaker, budgets, diagnostics aggregation, and audio/WebGL state machines;
- component tests for error/fallback boundaries;
- Playwright tests for browser lifecycle, DNT/GPC, recovery paths, and artifact production;
- existing V2 core tests and visual QA remain regression gates.

Where browser APIs are optional, tests use deterministic capability injection rather than asserting unsupported behavior.

## 12. Success criteria

V2.1 is complete only when all of the following are true:

1. local-only observability is the default and makes no external telemetry request;
2. external adapters are provider-neutral, optional, lazy/conditional, sanitized, and failure-isolated;
3. DNT/GPC suppress analytics adapters;
4. no component calls Sentry/Plausible/GA4 directly;
5. one authoritative frame stream feeds both adaptive quality and diagnostics;
6. normal desktop/mobile journeys satisfy hard CI safety gates and emit diagnostics artifacts;
7. runtime renderer/WebGL failures degrade to narrative-preserving fallback without loops;
8. audio lifecycle remains user-consent-safe and idempotent;
9. V2 cinematic timing and interaction semantics remain unchanged;
10. exact-head PR CI passes before merge;
11. resulting `main` GitHub Pages build/deploy succeeds from the merge SHA.

## 13. Follow-on boundary

V3 begins only after V2.1 hardening is merged and verified. V3 may consume the observability/performance APIs added here, but V2.1 must not pre-implement V3 visuals, scene transitions, autoplay guided-tour features, or new narrative functionality.
