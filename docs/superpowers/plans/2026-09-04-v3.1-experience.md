# V3.1 Experience Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add interruptible cinematic autoplay, shared guided chapter navigation, and canonical chapter deep-links without changing the V3.0 rendering/continuity architecture.

**Architecture:** Keep the existing chapter timeline, Zustand store, real document scroll, and V3.0 `globalProgress` rendering pipeline authoritative. Add pure navigation/autoplay models, one DOM-facing journey controller hook, and compact controls; all guided/autoplay movement writes to the same real page scroll that manual navigation already uses.

**Tech Stack:** React 19, TypeScript 5.9, Vite 8, GSAP ScrollTrigger, Zustand 5, Vitest 4, Node core tests, Playwright 1.62 Chromium.

**Spec:** `docs/superpowers/specs/2026-09-04-v3.1-experience-design.md`

## Global Constraints

- Preserve exactly ten semantic chapter IDs, current order, scenes, and authored copy.
- Option A is authoritative: autoplay can pause/resume, but explicit user navigation immediately wins.
- Autoplay is opt-in; never auto-start on initial page load.
- Keep one chapter timeline, one Zustand store, one real document-scroll source, one renderer, and the existing V3.0 camera/continuity pipeline.
- Canonical links are `#chapter-<chapter-id>`; unknown hashes fail closed.
- Reduced motion never uses continuous rAF auto-scroll; use chapter-step playback with instant navigation.
- Programmatic scroll events are not manual-takeover signals.
- Do not add router, UI framework, analytics provider, or renderer dependency.
- Existing V2.1 WebGL recovery, observability, DOM fallback, adaptive quality, and audio contracts remain intact.
- Exact PR head must have `check` and `e2e` GREEN before merge.
- V3.2 Capture & Quality remains out of scope until V3.1 is merged and verified on `main`.

### Task 5: Interruptible autoplay and reduced-motion step mode

**Files:**
- Modify: `tests/journey-navigation-v3.1.test.tsx`
- Modify: `src/experience/useJourneyNavigation.ts`

**Interfaces:**
- Uses Task 2 `reducePlayback`, `advancePlaybackProgress`, and `nextReducedMotionChapterIndex`.
- Continuous autoplay duration constant: `AUTOPLAY_TOTAL_DURATION_MS = 120_000`.
- Reduced-motion chapter hold constant: `REDUCED_MOTION_CHAPTER_HOLD_MS = 6_000`.

- [ ] **Step 1: Add failing autoplay/controller tests**

Assert with fake timers/rAF:
- Play from manual starts ordinary autoplay and advances page scroll from current progress.
- Pause cancels future advancement and keeps current progress stable.
- Resume reads current store progress and continues.
- completion moves to `completed` and cancels the loop.
- Play from completed restarts page progress at 0 before advancing.
- `wheel`, `touchstart`, `touchmove`, and supported navigation keys dispatch takeover and cancel autoplay.
- key events from `input`, `textarea`, `select`, or contenteditable targets do not trigger takeover.
- programmatic `scroll` alone never triggers takeover.
- reduced-motion Play uses a chapter-step timer, never requests a continuous rAF scroll loop, and completes at epilogue.

- [ ] **Step 2: Run focused test and verify RED**

Run: `npx vitest run tests/journey-navigation-v3.1.test.tsx`
Expected: FAIL on missing autoplay/takeover/reduced-motion behavior.

- [ ] **Step 3: Implement ordinary-motion autoplay**

While mode is `playing` and reduced motion is false, schedule one rAF. Compute delta from the previous animation timestamp, advance normalized progress with Task 2, convert to current scroll pixels, and call `window.scrollTo({ top, behavior: 'auto' })`. When progress reaches 1, dispatch `complete` and cancel the loop.

- [ ] **Step 4: Implement manual takeover listeners**

Install `wheel`, `touchstart`, `touchmove`, and `keydown` listeners while playback is playing or paused. A supported user-navigation event dispatches takeover and cancels active rAF/timers. Ignore navigation keys from editable elements.

- [ ] **Step 5: Implement reduced-motion chapter-step autoplay**

While reduced motion is true and mode is `playing`, use one timeout. At each timeout, advance to `chapterIndex + 1` with instant navigation and schedule the next hold. At epilogue dispatch `complete`. Pause/takeover cancels the timeout; Resume schedules from the live current chapter.
