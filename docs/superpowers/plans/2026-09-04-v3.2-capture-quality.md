# V3.2 Capture & Quality Implementation Plan

> **For agentic workers:** implement task-by-task with strict RED -> GREEN discipline. Use the merged/deployed V3.1 + Pages-hotfix baseline only; do not mix runtime feature work into this carrier.

**Goal:** Produce deterministic, persistent, machine-verifiable visual evidence for the stellar journey on every PR without introducing checked-in pixel baselines or runtime capture functionality.

**Architecture:** A pure test-side capture plan defines 23 stable checkpoints. Playwright writes per-profile PNGs and manifests under `v3.2-captures`; a dependency-free Node validator verifies exact coverage, safe paths, PNG integrity, dimensions, byte counts, and SHA-256, writes JSON/Markdown summary, and CI uploads the evidence as a dedicated artifact.

**Spec:** `docs/superpowers/specs/2026-09-04-v3.2-capture-quality-design.md`

## Global constraints

- Baseline: `d911f7b79c2c0b5044a678d0c5f647ba988f3dbe`.

- Preserve V3.0 continuity/camera/scenes and V3.1 autoplay/guided/deep-link behavior.

- [ ] **Step 2: Confirm RED**

- [ ] **Step 3: Implement PNG/header/hash validation**

Use only Node built-ins:

- `node:fs`
- `node:path`
- `node:crypto`
- `node:url`

PNG signature:

```text

```

- manifest `file` must equal the exact `captureRelativePath(case)`;
- resolve against root and ensure it remains inside root.

Minimum size = 4096 bytes.

### Task 3: Browser capture helper and manifest writer

**Files**
- Create: `tests/e2e/support/v3.2-capture.ts`

**Browser helper responsibilities**

- create/clear only the active profile directory;
- inject capture-only CSS stabilization;
- wait for fonts;
- navigate to chapter fraction by DOM geometry with scroll smoothing disabled;
- assert active chapter;
- wait two rAF turns + bounded settle;
- capture viewport PNG with Playwright `animations: 'disabled'`;
- parse PNG dimensions;
- calculate SHA-256;
- write `CaptureManifestEntry`;
- write manifest only after all profile cases succeed.

- [ ] **Step 1: Add RED Playwright spec**

1. `desktop V3.2 writes the complete 19-capture manifest` — runs only `chromium-desktop`;
2. `mobile V3.2 writes the representative 3-capture manifest` — runs only `chromium-mobile`;
3. `reduced-motion V3.2 writes the representative capture manifest` — runs only `chromium-desktop`, calls `page.emulateMedia({ reducedMotion: 'reduce' })`.

Each test asserts:

- expected case count;
- no page/console breaking errors;
- every planned PNG exists by successful capture call;
- manifest profile/count/IDs match the plan.

Expected initial RED: helper module missing.

- [ ] **Step 2: Implement stabilization**

Inject:

```css
html { scroll-behavior: auto !important; }
*, *::before, *::after { animation: none !important; transition: none !important; caret-color: transparent !important; }
```

Do not hide experience UI or canvas.

Wait `document.fonts.ready` if available and two rAF turns after target scroll.

- [ ] **Step 3: Implement deterministic placement**

For each case:


Clamp to >= 0 and use `window.scrollTo(0, target)` while capture CSS disables smooth scrolling.

Boundary case active chapter remains outgoing chapter.

- [ ] **Step 4: Implement manifest write**

Record CSS viewport from `page.viewportSize()` and actual PNG dimensions from buffer.
